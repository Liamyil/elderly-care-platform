4上线前的四道门槛　技术已不是主要瓶颈

A

资金与支付合规

最高优先
  • 当前为模拟支付（下单即成功、无真实扣款），需申请微信支付商户号并接入 JSAPI 支付 V3 + 回调验签。
  • 平台代收陪诊费再结算给互助员，存在"二清"风险。需选择：服务商分账模式 / 互助员直收 / 灵活用工结算通道。这条决定商业模式，建议优先决策。
  • 互助员人民币余额可提现，形成平台资金池，需明确资金存管与对账机制。
B

资质与隐私合规

上线前置
  • 小程序类目与资质：养老服务、家政类需营业执照对应经营范围；陪诊涉医疗周边，审核可能要求医疗相关资质，建议提前与平台预审沟通。
  • 隐私合规：需补《隐私政策》《用户协议》正文、个人信息收集清单；健康评估数据属敏感个人信息，须单独同意。
  • 互助员身份核验：实名认证与无犯罪记录核验当前未接入，上门服务场景下属必要项。
C

技术与运维

约 2–3 周
  • 登录验证码当前固定为 123456，需接真实短信服务并做频率限制。
  • 部署方式为本地电脑 + 临时内网穿透，需迁移至云服务器 + 备案域名 + HTTPS。
  • 图片存本地磁盘（151 张），需转对象存储 + CDN；数据库需定时备份、异地留存。
  • 密钥与数据库口令目前写在配置文件中明文，需改环境变量 / 密钥管理；补监控告警与错误日志收集。
  • 代码版本仅 5 次提交，建议立即规范 Git 提交与远程仓库备份，避免单点丢失。
D

运营与风险兜底

非技术，决定成败
  • 互助员供给：首批从哪来？建议依托社区 / 街道现有志愿者、网格员、退休医护转化。
  • 保险：上门服务责任险 + 互助员意外险，一本保单的成本远低于一次纠纷。
  • 冷启动：老人不会用手机，需社区工作人员代下单或家属端承接，建议配 1 名驻点运营。
  • 服务纠纷处置流程与平台责任边界需书面明确（平台是信息撮合还是服务提供方）。

5建议的上线路径　先跑通一个社区，再谈规模

阶段一　演示验收

本周 · 已就绪

三端演示环境就绪，完整闭环可现场走通（发单 → 接单 → 打卡 → 确认 → 结算 → 评价），后台可实时查看数据。重点演示时间币双轨结算与服务留痕两个差异化能力。

阶段二　单社区灰度试点

4–6 周

锁定 1 个社区，20–30 位老人、6–10 位互助员，真实跑单。此阶段补齐：提现与退款入口、待支付单管理、真实短信、云部署与 HTTPS、互助员实名核验、服务保险。
支付可先采用线下结算或互助员直收，绕开二清问题，把业务真实性验证放在第一位。

阶段三　合规化正式运营

2–3 个月

完成支付分账方案落地、资质与隐私合规、SOS 接真实通道与值守、老人档案与重点关爱、信用积分体系，具备多社区复制条件。同步启动二期（探访任务、监管大屏）。

6需要周总决策的三件事

01

试点落在哪里，有没有社区 / 街道背书

互助养老的核心壁垒不是系统，是信任与供给。有社区背书，互助员招募和老人信任成本都会降一个量级；若能对接政府购买服务或时间银行试点政策，还能解决一部分资金来源。

02

钱怎么走：平台代收，还是互助员直收

平台代收体验最好，但需要分账资质或第三方结算通道，且形成资金池；互助员直收最快上线、合规成本最低，但抽佣与对账要另做设计。建议试点期先直收，验证需求后再升级代收 + 分账。

03

投入：运营人手 + 基础服务采购

上线不是开发完就结束：需 1 名驻点运营（带老人用、盯订单、处理纠纷）、云服务器与域名备案、短信服务、服务保险。这几项合计投入不大，但缺一项都上不了线。
