**智慧互助养老平台整体实现方案**

**一、方案概述**

**1.1 建设背景**

依据民政部等11部门《关于推进互助性养老服务发展的意见（2026）》、《基本养老服务综合平台试点方案》等国家顶层政策要求，围绕**低龄帮高龄、健康帮弱疾、邻里互助、智慧赋能、全程留痕、可监管可激励**核心目标，建设一体化智慧互助养老服务平台。

针对传统互助养老存在的需求对接无序、服务无记录、激励无抓手、监管无数据、重点老人关爱不到位五大痛点，通过小程序移动端+云端管理后台+IoT智能感知+时间银行数字化体系，实现社区互助养老标准化、智能化、常态化落地。

**1.2 核心定位**

构建**政府监管+社区运营+老人自主服务+邻里互助+时间银行激励+智能安全守护**六位一体的智慧互助养老体系，支撑日常互助、紧急救助、定期探访、积分激励全业务闭环。

**1.3 核心业务规则（最终确认版）**

1、需求发起双模式：**以老人/家属自主发起订单为主，平台/社区管理员下发指派订单为辅**；

2、订单调度双模式：**普通需求系统自动抢单、重点/紧急需求人工手动派单**；

3、互助员统一通过**微信小程序接单、履约、留痕、结算**，全程移动端闭环。

**二、政策合规依据**

1、**民政部等11部门《关于推进互助性养老服务发展的意见》（2026年）**：明确支持互联网+互助养老、线上需求对接、智能精准匹配、服务全程留痕、时间银行数字化管理、跨区域通存通兑。

2、**民发〔2024〕17号 基本养老服务综合平台试点通知**：要求养老服务供需精准对接、智能派单、台账数字化、一网监管。

3、**智慧健康养老产业发展行动计划**：支持平台化预约、派单、评价、信用管理、志愿服务积分激励体系建设。

4、民政常态化考核要求：特殊困难老人月度探访全覆盖、服务可追溯、问题可预警、数据可上报。

**三、总体架构设计**

**3.1 五层技术架构**

**感知层**：智能手环、SOS紧急按钮、跌倒雷达、智能门磁、烟感、蓝牙健康监测设备，实现老人安全与健康数据实时采集。

**网络层**：4G/5G、蓝牙、MQTT物联网协议，加密传输、设备双向认证，保障数据安全。

**数据中台层**：统一用户账号体系、老人档案库、互助订单库、时间银行区块链账本、IoT设备台账、服务评价库。

**业务应用层**：老人小程序、互助员小程序、社区管理后台、街道民政监管大屏。

**监管展示层**：数据可视化大屏、报表自动生成、民政数据对接、服务质量审计。

**3.2 系统角色体系**

六大角色全覆盖：老人、家属、社区管理员、街道民政管理员、互助员（低龄老人/志愿者）、系统超级管理员。

**四、核心业务模式（重点：订单发起与派单规则）**

**4.1 订单需求发起双模式（定稿）**

**模式一：老人/家属自主发起（主力日常场景）**

适用：普通高龄老人、日常高频互助服务（助购、助洁、陪聊、陪诊、代办、日常陪伴）。

操作流程：老人/家属小程序填写服务类型、服务时间、地址、需求描述 → 提交发布 → 进入公开订单广场 → 互助员抢单履约。

**模式二：平台/社区管理员下发订单（兜底+监管场景）**

适用：独居、空巢、失能、特困、重度残疾等重点关爱老人；月度定期探访、固定帮扶任务；无人接单超时兜底；紧急事件处置。

操作流程：管理员后台手动创建任务/系统自动生成周期性探访任务 → 指派专属互助员 → 互助员小程序接收指派单、必须响应履约。

**4.2 订单调度双模式（自动+手动结合）**

**1、自动抢单模式（普通需求）**

老人自主发布的普通需求，审核通过后公开至订单广场，范围内符合技能、空闲状态的互助员可自主抢单，先到先得，系统自动匹配距离、服务评分、接单量最优人员。

超时规则：订单发布15–30分钟无人接单，自动流转至后台待派单池，转为人工兜底派单。

**2、手动指派模式（重点/紧急/计划任务）**

重点人群、定期探访、紧急求助、专项帮扶订单，不公开抢单，由社区管理员根据互助员位置、技能、排班情况手动指派。

管控规则：指派订单不可随意拒单，无故拒单计入信用扣分，保障特殊老人服务兜底。

**4.3 互助员接单形式（最终落地方式）**

所有互助员统一通过**微信小程序**完成全部操作：查看广场抢单、接收管理员指派单、上门打卡、服务留痕、完成确认、查看时间币到账明细，轻量化、零下载、易推广。

**五、各端详细功能设计**

**5.1 老人/家属小程序端**

1、自主互助下单：选择服务类目、预约时间、填写需求、上传图片，一键发布；

2、紧急SOS求助：绑定智能手环/按钮，一键告警，联动家属、互助员、社区；

3、订单管理：查看待接单、服务中、已完成、已取消订单；

4、服务评价：服务完成后打分、留言评价；

5、时间银行查询：查看本人服务时长、兑换记录、明细账单；

6、健康管理：设备数据同步、用药提醒、健康记录查看；

7、代下单功能：支持家属、网格员代为发起互助需求。

**5.2 互助员小程序端**

1、实名认证与技能备案：填写个人信息、服务技能、服务范围，审核通过方可接单；

2、订单广场抢单：查看周边公开互助订单，自主抢单；

3、指派订单接收：接收社区下发专项任务，待确认、待履约；

4、上门履约留痕：定位打卡、现场拍照、填写服务记录；

5、时间银行台账：服务完成自动到账，可查询、可兑换、可转赠；

6、信用积分中心：查看服务评分、拒单记录、信用等级。

**5.3 社区/街道管理后台PC端**

1、老人档案管理：重点老人台账分类、风险等级标注、关爱周期设置；

2、订单全流程管理：需求审核、待派单管理、手动指派、超时订单处理；

3、互助员管理：招募审核、培训管理、排班管理、信用考核、接单权限管控；

4、定期探访任务：系统自动生成月度探访计划、批量派单、异常问题登记；

5、时间银行管理：时长审核、兑换审批、转赠继承、区块链存证对账；

6、服务质量监管：查看所有服务轨迹、照片、评价、投诉处理；

7、报表台账自动生成：满足民政上报标准，一键导出探访记录、服务统计、人员台账。

**5.4 智慧监管大屏**

展示辖区老人分布、互助员分布、订单热力图、服务完成率、重点老人关爱覆盖率、时间银行总存量、异常告警数据、超时未处置任务，实现可视化监管。

**六、四大核心业务流程（标准落地流程图）**

**6.1 日常互助服务流程（自主发单+抢单）**

老人/家属发布需求 → 社区审核通过 → 订单公开至广场 → 互助员抢单 → 上门打卡履约、拍照留痕 → 老人确认+评价 → 系统自动结算时间币入账 → 台账归档

**6.2 重点老人帮扶流程（平台下发+手动派单）**

后台重点老人建档 → 系统生成周期性任务/管理员新建专项任务 → 手动指派互助员 → 互助员确认接单 → 上门探访/服务、填写记录表 → 后台审核 → 异常跟进处置 → 生成民政合规报表

**6.3 紧急救助流程**

老人触发SOS/设备检测异常 → 平台实时告警 → 同步推送家属、就近互助员、社区管理员 → 就近人员上门处置 / 联动120应急 → 险情解除关闭告警 → 全流程记录归档

**6.4 时间银行激励流程**

服务完成双方确认 → 系统按标准折算时长 → 区块链存证入账 → 支持本人兑换服务/实物、亲属转赠、继承 → 后台审核兑付 → 生成流水台账

**七、核心机制设计**

**7.1 订单超时兜底机制**

公开抢单订单超时无人接单，自动转入后台待派单池，由社区管理员人工兜底指派，杜绝老人需求无人响应。

**7.2 互助员信用管控机制**

实名认证、岗前培训准入；指派单无故拒单扣分、多次违规限制接单；服务评分与接单优先级挂钩，优质互助员优先派单。

**7.3 时间银行区块链存证机制**

服务时长上链存证，不可篡改，支持通存通兑、转赠、继承、兑换，满足国家互助养老信息化建设标准。

**7.4 重点老人关爱机制**

独居、空巢、失能、特困老人标记重点标签，默认禁用自主抢单模式，全部采用平台手动指派，确保服务精准、责任到人、关爱全覆盖。

**八、技术实现方案**

**后端框架**：SpringBoot + SpringCloudAlibaba 微服务架构，稳定可扩展，适配政务系统对接

**前端框架**：Vue+ElementUI（管理后台）、Uni-app（微信小程序，兼容所有机型）

**数据库**：MySQL（业务主数据）、Redis（缓存与订单并发）、MongoDB（存储服务图片、记录文档）

**物联网**：MQTT协议、边缘网关统一设备接入，实时告警、状态监测

**安全规范**：等保三级适配、数据脱敏、操作审计日志、RBAC分级权限管理

**存证技术**：区块链时间银行账本，满足数据不可篡改、可追溯要求

**九、落地实施步骤**

**第一阶段：基础能力搭建（1个月）**：完成小程序两端、后台管理、订单双模式、时间银行基础功能，跑通发单-接单-服务-结算闭环。

**第二阶段：智能硬件与安全体系（2个月）**：接入IoT智能设备、紧急告警、健康监测、风险预警功能。

**第三阶段：监管与合规闭环（3个月）**：完成数据大屏、民政报表、台账自动生成、政策合规验收、试点社区落地运行。

**十、方案优势与合规亮点**

1、完全贴合2026国家互助养老最新政策，适配民政考核指标；

2、双模式订单体系，兼顾老人自主便捷与重点人群兜底监管；

3、小程序轻量化接单，运营成本低、老人与志愿者上手简单；

4、全流程留痕、数据可溯、台账自动生成，满足政务上报要求；

5、区块链时间银行激励体系，解决互助养老可持续运营难题。
